# Stop the Train — BACKEND (game server)

Frontend (3D client) lives at `..\Stop-the-train`. Colyseus 0.18 + Mongo. A contract change goes in both projects.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`, generated), `npm test` (mocha + `@colyseus/testing`; Mongo faked via `__setPlayersForTest`, Bloxity HTTP faked via `__setFetchForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`). Client calls `joinOrCreate("world", { userId, username, pfp, token, avatar, pose })`. Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable. `/health` for Legion; `/monitor` and the playground are dev-only.
- **Identity** (`WorldRoom.applyIdentity`): with `token` (`Legion.SDK.auth.getToken()`), `src/bloxity.ts` `verifyToken` POSTs `{BLOXITY_API_URL}/v1/auth/game-token/verify` (Bearer token, body `{gameSlug}`; slug = env `BLOXITY_GAME_ID`, else `GAME_SLUG_DEFAULT` placeholder in `constants.ts`). Valid -> account id `legion_<user._id>`, username/pfp from the verified user. Invalid / unreachable -> guest (no persistence). Without a token, `userId` is trusted ONLY when `NODE_ENV !== "production"` (dev ids `dev-...`); `guest-` ids never saved. Message `identify { userId, username, pfp, token }` re-runs this after a mid-session sign-in/out. A second live session on the same account is evicted. Carry-over: a verified account with no doc copies the first existing, not-yet-`carriedTo` doc among `carriedFrom` ids and marks the source `carriedTo`.
- **Saved progress**: `saveProgress` = whole snapshot (ignored until `loaded`): `coins, power, luck, multiplier, rebirths, breaks, robux, strength, powerMult (>=1), levels {id:int} (magnet, carry, cooldown, fuse, walkspeed; ID_PATTERN, max LEVEL_KINDS_MAX), trainsStopped {tierId:int} (the train book, known TRAIN_IDS only), dailyAt, dailyDay, chestAt, updateEnds (unix s), seeded, muted, lastSeen, playtime`; ceilings in `constants.ts` (currency 1e18, rebirths 1e9). Server -> client (private): `progress` (doc + `serverTime`), `noProgress { serverTime }`, `serverError` (read failed: saving stays off). The daily cooldown lives client-side in the snapshot. **Free coins chest** is server-owned (`CHEST` in `constants.ts`): the room counts 1 s per tick of play for each session whose save is loaded and whose tab is visible (`visible {on}`), stores it as `chestPlay` in the doc (not accepted from `saveProgress`), and sends `chest {play}` after load and every 10 s. `claimChest` -> `chestResult {ok, coins, play}`: ok only at `CHEST.playSeconds` (30 min), then resets to 0; the client adds `CHEST.coins` (10K). A verified `adReward` with placement `chest-refill` fills the count.
- **Presence** (`src/presence.ts`): roster `PlayerState`: `username, signedIn, pfp, world, x, y, z, yaw, speed, grounded, vy (+-200), carry (sanitised JSON string, "" = none: one vehicle {"type","paint","variant"}, a stack an array of them bottom first, <= CARRY_MAX_COUNT, max CARRY_MAX_LEN), bench (int8, -1 = not training, 0..63), benchRep (0..1), avatar (Bloxity look JSON, max AVATAR_MAX_LEN, never parsed), emote, emoteSeq (uint32, +1 per accepted emote message)`. Messages: `pose {x,y,z,yaw,speed,grounded,vy}` (~10-15/s, world within +-2000 m; also accepted in join options), `carry {specs:[{type,paint,variant}, ...]|null, spec: the first one|null}` (`spec` alone still works), `train {bench:int|-1, rep}`, `setAvatar {avatar}`, `emote {id}` (slug <= 64 chars, "" stops).
- **Leaderboards**: Mongo top-10 (`src/leaderboard.ts`) for `LEADERBOARD_STATS` = `rebirths, breaks, strength`; `leaderboard { boards:{stat:[{name,value}]}, ranks:{stat:n|null} }` sent after load and every `LEADERBOARD_EVERY_MS`. Additionally `src/reporter.ts` batches saved scores of `legion_` accounts (`#m...` stripped) and flushes every `REPORT_EVERY_MS` (15 s), on room dispose and on shutdown to `POST {API}/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report` (Bearer `BLOXITY_REPORT_TOKEN`, <= 200 scores/call; no-op if either env is unset). Board declarations = the single `BLOXITY_BOARDS` constant (the frontend declares the same via `Legion.SDK.leaderboard.define`).
- **Rewarded ads**: `adReward { token, placement }` -> `POST {API}/v1/ads/reward/verify {gameSlug, rewardToken}`; answers `adResult { ok, placement, reason?: "bad" | "used" | "invalid" }`. Tokens are single-use (bounded in-memory set per room). The server only attests; the client grants. No gems/webhook.
- **Env** (see `.env.example`): `BLOXITY_API_URL, BLOXITY_MATCHMAKER_URL, BLOXITY_PORTAL_URL, BLOXITY_STATIC_URL, BLOXITY_REPORT_TOKEN, BLOXITY_GAME_ID, BLOXITY_CHANNEL, CLIENT_ORIGIN, JWT_SECRET, MONGODB_URI, PORT, POD_NAME`.
- **Shutdown**: on SIGTERM Colyseus stops accepting joins and disposes rooms (`onDispose` flushes scores); `index.ts` `app.onShutdown` then flushes once more and closes Mongo.
- **CI/CD** (`.github/workflows/deploy.yml`): tests on PRs/pushes to `main`/`dev`; pushes deploy via a matrix over targets (`prod` always, plus `staging` when secret `LEGION_DEPLOY_TOKEN_STAGE` exists; `workflow_dispatch` input `target` runs only that one). prod: `LEGION_DEPLOY_TOKEN` -> `https://legion.bloxity.io`; staging: `LEGION_DEPLOY_TOKEN_STAGE` -> `https://legion.stage.bloxity.io` (fails if empty, never falls back). Image tag `<channel>-<target>-<sha>` (main = channel prod, dev = dev). `roomSize` = `ROOM_MAX_CLIENTS` from `src/constants.ts` (keep 2-100, no `seatCap`). The GHCR package must be public. Needs var/secret `LEGION_GAME_ID`.

- **Shared round** (`src/round.ts`, tuned by `ROUND` / `TRAIN_TABLE` in `constants.ts`, mirrors the frontend `ROUND`/`TRAINS`): one rail and one train per world of a room, server-authoritative. In: `park {id, spec:{type,paint,variant,hp}, x, halfLen, from|null}` (<= `perPlayerCap` each, `railCap` total; refusal = `railRefuse {id}` to the sender), `seedRail [{spec,x,halfLen}]` (once per world). Out (to the players in that world): `round` snapshot (also to each joiner and on a world change; train start; carries `world`), `railAdd`, `trainTick {head,speed}`, `hit {id,by,damage,capped,hp,speed}`, `derail {idx,contributors:[sessionId],pay:{sessionId:coins},streak,step,milestone:{n,coins}|null}`, `gone {result:'stopped'|'through', hpLeft, ...snapshot}`; the snapshot also carries `maxHp, reward, step, streak, losses, comeback, underdog, stopped`. In: `stats {power, carry}` (each client, whenever what it can lift changes).
- **Fair trains** (`src/fair.ts`, tuned by `FAIR` in `constants.ts`, mirrored by the frontend `fair.js` / `FAIR`): a train's HP = room power (sum of each present, visible player's best liftable vehicle (`BAYS`) x Carry, from `stats`) x `targetRatio` x the ladder x a random spread; it is sized at countdown start and again as it leaves. The tier with the nearest HP gives the look (`idx`), the reward follows the tiers' coins on a log-log line. Ladder: a derail is `ladder.win` steps up, a train through `ladder.loss` steps down (not when the world is empty), so rooms settle near 60% stopped; `comebackAfter` losses in a row make an X2 COMEBACK train; idle worlds reset. While others have vehicles in the pass one player's damage is capped so the others' vehicles always count (`damageCap`). The derail reward (X2, streak bonus) is split by damage: floor `rewardFloor`, overkill halves, the room's weakest player (`underdog`) +50%. Every `milestone.every` trains a world stops pay everyone there. Train luck is not per player.
- **Worlds** (`WORLDS` in `constants.ts`, mirrors the frontend `WORLDS`: `main`, `galaxy` at 36 rebirths): a world is a part of the room, not a room of its own, so a room's `ROOM_MAX_CLIENTS` covers all its worlds and friend invites keep working. `WorldRoom.rounds[id]` is that world's `Round`; `PlayerState.world` says where a player is (every join starts in `main`; not saved), the client draws only its own world's roster entries, and `sendToWorld` narrows the round's messages. `setWorld {world, rebirths}` moves the sender and answers with that world's `round`, or `worldRefused {world}` when the rebirths fall short: an account is judged by its save (`WorldRoom.rebirths`, from the loaded doc and every `saveProgress`), a guest has no save and states its own. The client resends `setWorld` once a (re)joined room has read its save.
